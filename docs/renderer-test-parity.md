# Renderer test parity

The Ant Design and shadcn suites exercise the same supported specification areas through their real renderer registries and native controls. Comparable coverage means preserving the observable contract, including writes, guards, errors and external updates. File names, component structure and test counts differ between adapters.

## Shared regression contracts

`renderer-common/test/contracts/additionalPropertyClearing.tsx` runs unchanged against both renderer registries. It distinguishes clearing text from deleting its dynamic property, including empty and dotted literal keys and schema defaults. New regressions affecting both adapters should use a shared contract when the observable interactions permit it; adapter-specific selectors belong in the adapter.

Common hooks and factories also have independent tests for tuple writes, mixed navigation, composition dispatch, isolated drafts, row detail, selection, resize, masking, context boundaries, validation navigation and web-component input. Those tests verify shared logic; they do not replace registry-level adapter tests.

## Running and maintaining the comparison

Run `pnpm test` for the workspace suites. Run `pnpm --filter @chobantonov/jsonforms-react-renderer-common run test-cov` for common-package coverage. Common coverage includes every source module and enforces at least 85% statements, branches, functions and lines; consumer tests and coverage exclusions are not used to meet that threshold.

When an Ant Design test adds a portable behavior, add its shadcn counterpart or extend a shared contract in the same change. Retain negative assertions and stored-data checks when adapting native DOM queries. A suite that mounts an example without checking its behavior does not establish parity.

## Verification limits

These suites use jsdom. Layout, pixel placement, real pointer geometry, native picker dialogs, screen-reader output and browser performance need browser/manual verification. Monaco is replaced with an editor boundary in integration tests; editor publication and host behavior remain real. Some focused grid tests replace the grid boundary, while the array and deletion examples also exercise real AG Grid. Ant Design-specific rc component details and shadcn-specific Radix/Base UI details have separate tests where applicable. This map is not certification that every specification vector or browser interaction has been executed.
